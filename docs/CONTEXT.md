# CONTEXT — このリポジトリの運用語彙

このリポジトリ（汎用 Claude Code 自律運用ベース）に固有の語だけを載せる **索引**。
一般的なプログラミング用語は載せない。

> 🔴 **正本がある語について、ここは定義を持たない。** 定義は正本ファイルにあり、本ファイルは
> そこへのポインタと **使わない表記（`_Avoid_`）** だけを持つ。定義を書き写すと正本と索引の
> 二重管理になる（分散 SSOT 規律は維持する。各ルールファイルが冒頭で「このファイルは〇〇の
> 唯一の正本」と宣言する運用はそのまま）。
>
> **例外**: 正本がどこにも存在しない語 — つまり「割れている」のが表記ではなく **意味そのもの**
> である語 — に限り、**本ファイルがその語の正本になる**。索引に留めようがないため（指す先が無い）。
> 該当するエントリには 🔵 を付けて区別する。正本を持つ語と混ぜない。

## 収録基準

**表記が実際に割れている語だけ** を載せる。定義箇所で既にインラインの用語整理をしている語は載せない
（例: `session-safety-rules.md` ルール 1 の「ターン」は、定義直後に「サブエージェント並列数とは
別軸」と自ら断っているので、索引は不要）。**索引が長いこと自体に価値はない。**

## 語彙

**既約境界外リスト**:
ユーザーの最終判断を要するアクションの列挙（A-1〜A-6）。定義・全文は
`docs/rules/user-confirmation-minimization.md` §1。
_Avoid_: 境界外リスト, 既約境界外（単独）, 「境界外」リスト

> 補足: `A-1〜A-6（既約境界外）` のように **括弧内の注記** として使う形は許容する
> （リストそのものを指しているのではなく、そのアクションの属性を言っているため）。
> 「境界内 / 境界外」を **対比** として使う形（`autonomous-operation-policy.md`）も別用法として許容。

🔵 **パイプライン**（本ファイルが正本）:
スキルが駆動する、定義済みの一連の工程（対象の検出 → 実装 → PR → レビュー → マージ）。
`.claude/skills/*/SKILL.md` が Step 0..N として持つもの。

🔵 **ワークフロー**（本ファイルが正本）:
**パイプライン** より上位の、作業の流れ全般。および GitHub Actions の workflow / `Workflow` ツール。
_使い分け_: 「どのスキルの、どの Step か」を指せるなら **パイプライン**。指せないなら **ワークフロー**。

> この 2 語は **47 ファイル対 37 ファイル** で使われ、**22 ファイルが両方を含む** にもかかわらず
> 使い分けの定義がどこにも無かった（`problem-investigation-protocol.md:3` は同一文で両方を
> 並列使用している）。指す先が無いため上記が **本ファイル発の定義** であり、これが例外条項の
> 該当例。**既存の全面置換はしない** — 新しく書くときに上の基準で選び、明らかな誤用に
> 気づいたときだけ直す。

## 使い方

新しい運用語彙を導入する前に本ファイルを grep し、既存表記があれば揃える
（手順は `docs/rules/lessons-management.md`）。ここに無い語を新設するときは、
**その語が本当に新しい概念か**（既存語の言い換えでないか）を先に確かめる。
