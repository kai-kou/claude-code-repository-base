# セッション完了報告ルール — 詳細版（Warm 層）

> **本ファイルは `completion-report-rules.md`（Hot・SSOT）の詳細補完版**。
> Hot 層予算の再棚卸し（#369）で良い例 / 悪い例の具体テキストを本ファイルへ移設した（サマリー＝ポインタ規約）。
> 判定ロジックの実体は `stop-completion-report-check.sh`（Stop hook）が持ち、Hot 層の「鉄則」5 項目が判断基準として常駐する。

## ✅ 良い例

```markdown
## ✅ 完了報告

**ご依頼**: 完了報告を「PR マージ詳細」ではなく「初回指示のアウトカム中心」にするようルール・ハーネスを調整。
**できるようになったこと**: セッション完了時に依頼の再掲とアウトカムが冒頭に出るようになり、チャットを遡らずに「何を頼んで何が達成されたか」が一目で分かるようになったにゃ。

---
[PR #36](https://github.com/.../pull/36) / ブランチ `claude/...`
```

## ❌ 悪い例の典型

「PR #36 を squash でマージしました！指摘 3 件を解消、修正サイクルは 2 回でした。〇〇.md と △△.sh を更新しています」

→ 初回指示の再掲なし・アウトカムなし・プロセスとファイル名が主役。**これが「で、何頼んだっけ？」を生む**。

## 二重報告の根本原因と修正（#633・Hot 層 §1.2 から参照）

**症状**: 下流リポジトリで完了報告が 2 回出る。① `✅ 完了報告`（適正）→ ② PR 監視の通知 wake で
「対応不要、PR #N は無事マージ済みで完了にゃ」等の短い受領応答 → ③ **もう一度 `✅ 完了報告`**（短い書き直し版）。

**根本原因**: `stop-completion-report-check.sh` の処理順序。#543 で入れた「このセッションで一度適正な完了報告を
出した」マーカーによる nudge 抑止が、`stop_hook_active == true` の early return より **後** に置かれていた。

```
stop_hook_active == true → exit 0        ← 続行ターンはここで抜ける
...
is_proper_report → マーカー書き込み       ← 到達しない
classify_text == nudge → hook_block
```

本ベースの標準フローは「実装完了 → Stop → `stop-git-check` / `stop-pr-check` / `stop-publish-check` の
いずれかが差し戻す → **続行ターンで完了報告を出す**」が最頻経路であり、この経路ではマーカーが常に立たない。
その後 `subscribe_pr_activity` の webhook / 通知 wake（`stop_hook_active=false`）で短い受領応答を返すと、
`classify_text` が「マージ + PR 参照 + アウトカム語なし」で nudge と判定し `[report-format]` が発火する。

**修正（2 点の多層防御）**:

1. early return を **nudge 判定のスキップだけ** に限定し、マーカー記録は続行ターンでも必ず通す（主因）
2. `is_proper_report` の条件から `MERGE_RE` **だけ** を外す（`PR_REF_RE` は必須のまま維持する）。§1 テンプレートの
   完了報告は末尾に PR リンクを置くがマージ語を含むとは限らず、旧条件では「PR リンクはあるがマージと
   書かなかった完了報告」を取りこぼしていた
3. nudge 文言に「既に適正報告済みなら再掲も書き直しもしない」を明記する（ハーネスが取りこぼしても
   モデル側で止まる）

> 🔴 **`PR_REF_RE` の必須を外してはならない**（外すと #633 のセルフレビューで検出した回帰が戻る）: マーカーは
> セッション単位でタスク単位ではないため、PR に無関係なタスク（調査など）の適正報告 1 件でマーカーが立つと、
> 同一セッションの後続タスクが出した不適格なマージ報告まで nudge を素通りさせる。e2e⑦ がこれを固定している。
>
> **マーカー基準ディレクトリの `--absolute-git-dir` 化は見送った**: cwd 依存の除去を検討したが、git は
> リポジトリルートでのみ相対 `.git` を返し、サブディレクトリからは絶対パスを返す（どちらも同じディレクトリを
> 指す）ため差が出る経路を作れず、テストが vacuous になる。他のマーカー系フック（`post-pr-confirm-mark.sh` 等）と
> 同じ `--git-dir` のまま揃えてある。

回帰テストは `bash .claude/hooks/stop-completion-report-check.sh --self-test` の e2e ④〜⑦
（続行ターンでのマーカー記録 / その後の受領応答の抑止 / 続行ターンでは nudge しないこと /
PR 参照の無い適正報告ではマーカーを立てず後続タスクの不適格報告を nudge すること）。
